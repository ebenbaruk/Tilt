# Tilt in other coding agents

Tilt started as a Claude Code mod (`apps/mod`). This folder brings the same table to other coding agents ("harnesses"): one folder per agent, each with a `README.md` covering `## Install`, how to play, `## Uninstall` and `## Verified vs not`. Agents that can't draw a panel or capture keys use the **companion**, a terminal app you run in a split pane, and only tell it when the agent is working.

## Harnesses

Tiers, from most to least integrated:

1. **In-harness table with keys**: the table is drawn inside the agent's UI and you play with single keys.
2. **In-harness commands or status + companion**: commands, dialogs or a status item inside the agent; the companion for full keyboard play.
3. **Hooks + companion** (some with a status line): turn hooks feed the companion; a status line, when the agent has one, shows a one-line summary.
4. **Turn end only + companion**: the agent only reports when a turn ends.

"Docs only" means the files follow the agent's docs and source but were never loaded in that agent. Details and open questions are in each folder's `Verified vs not` section.

## Common concepts

- **`<TILT_DIR>`**: the absolute path of your clone of the Tilt client repo. Every install points at files in it, so keep the clone where it is. Recommended: `git clone https://github.com/ebenbaruk/tilt-client ~/.tilt/src`.
- **`TILT_API_URL`**: the Tilt API every client talks to, and the only server contacted. It must be `https`; plain `http` is accepted only on loopback (`127.0.0.1`, `localhost`, `[::1]`). Clients refuse to run without it.
- **The companion** (`companion/bin/tilt`): the full table in a terminal, played with single keys. Open it in a split pane next to the agent, for example `tmux split-window -h "<TILT_DIR>/harnesses/companion/bin/tilt"`; WezTerm, iTerm2 and Windows Terminal commands are in [`companion/README.md`](companion/README.md).
- **Files in `~/.tilt`** (all mode 0600):
  - `session.json`: the login token and table choices, shared by every Tilt client on the machine.
  - `agent.json`: the agent's working/idle state, written by `companion/bin/tilt-signal <working|idle>` from the agent's hooks (or by the in-harness plugins) and watched by the companion.
  - `status.txt`: the companion's one-line summary, printed by `companion/bin/tilt-status` for status-line harnesses; removed when the companion quits.
- **Privacy**: hooks only learn that a turn started or ended. `tilt-signal` and `tilt-status` never read stdin, which carries the prompt in several agents; plugins read only event timing or status, never prompts, replies, code, tool calls or transcripts.
- **Updating**: paste the install prompt again. It pulls, audits the new commit and waits for your go before reinstalling; never `git pull` the clone without that audit, since hooks and plugins run its files directly.
- **Shared core**: [`packages/play`](../packages/play) holds the harness-agnostic client (session, API client, the motion of a round playing out, and a terminal renderer). It draws the mod's own pane (`apps/mod/hooks/view.tsx`) and reuses its pure modules by relative path, so every harness that draws the table draws the same one as Claude Code. Those files are TSX: drawing the table needs a loader that compiles TSX with their own JSX pragmas (Bun does; jiti with `JITI_JSX=1`); plain Node's type stripping does not. `packages/play/src/core.ts` (the session without motion and the one-line status) imports plain TypeScript only: DeepSeek and Copilot run on it under plain Node and show one line, the companion draws their table.
